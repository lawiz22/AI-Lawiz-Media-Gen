# Minimax REF2v H3

[Documentation index](../README.md) | [Project overview](../../README.md)

Run **Video > Minimax REF2v H3** (violet), **Ultrafast** (green), or **MiniMax Advanced** (cyan) directly with a typed or pasted prompt. Video Prompt Generator is a separate, optional tool. Plain prompts do not require images; multimodal references are supported in REF2V. Advanced also offers first/last-frame conditioning and defaults to FL2V. Legacy preparation drafts remain stored locally.

The H3 prompt textbox highlights `<Picture N>`, `<Video N>`, `<Audio N>` and `<Subject N>` while you type, using the same color palette as Video Prompt Generator. It remains a native textarea with normal selection, copy/paste, resizing and synchronized scrolling; no switch to the prompt generator is needed.
Pasted zero-based subject labels such as `<Subject 0>` are also safe to display. Zero or oversized token numbers use the first color without changing the original prompt; this display behavior does not change reference validation when generating.

**Start from scratch** clears the current H3 prompt, every reference, pending audio edits, live preview and displayed output, and restores default H3/transcription settings. It asks for confirmation if a prompt, references or output would be discarded, including a warning about unsaved local output. Library items, ComfyUI files and the independent Video Prompt Generator are not changed. The fresh setup persists across reloads. Finish/cancel any active operation first. **Reset settings only** retains the prompt, references and displayed output and resets only the H3 settings.

## Workflow settings and six LoRAs

- **H3 REF2V** retains the supplied model/CLIP/dual-VAE choices, resolution selector, duration/frame expression, `seeds_2` sampler, Beta scheduler, intermediate sigma extension, ReferencePack and VHS output controls. Six independently enabled LoRA slots preserve the source strengths; all start disabled. Optional patched-CLIP conditioning is off, matching the source graph. Refresh loads installed model/LoRA lists and format-specific encoder widgets; **Check workflow** validates active nodes/models/options without uploading or queueing a job. Active settings are checked again before generation.

## Reference limits and token mapping

- Normal H3's reference capacity is **9 pictures / 3 videos / 3 standalone audio files**. Ultrafast and the independent prompt generator accept **6 / 2 / 2**; Advanced accepts **3 / 1 / 2**. Each reference can be disabled, and each video soundtrack can be excluded independently. Edited files are uploaded once without reapplying crops/trims. Sparse reference tokens are compacted by kind; available video soundtracks consume Audio labels before standalone audio. The server probe verifies silent videos before final audio numbering. Prompts mentioning missing/disabled references fail explicitly.

## Ultrafast

- Adapted from the supplied `0000-minimaxH3UltraFastest.json`, preserving `seeds_2`, **BasicScheduler beta / 5 steps / denoise 1**, **MiniMaxH3SigmaShift video 12 / audio 3**, **Comfy Kitchen attention**, the **INT8 convrot video VAE**, **0.3 MP / 4:3 / 2 seconds**, and native **CreateVideo / SaveVideo** automatic MP4 output. Output FPS and filename prefix remain editable; VHS-specific encoding, looping and temporary-output controls do not apply.
- Six independently enabled LoRA slots use **LTX_lora_loader** in `minimax` mode with the source stack format. All start disabled. The model chain is LoRAs, optional KJ preview, attention backend, sigma shift, then optional Spectrum for the guider. The scheduler uses the pre-shift attention model, matching the supplied graph.
- LoRA files use real dropdowns populated from the installed ComfyUI catalog, automatically loaded when the renderer opens. Enable the chain, then a slot to show its file/strength controls; inactive slots do not mount large option lists. **Refresh nodes / models** reloads the catalog explicitly; errors are shown without blocking prompt editing. Existing saved filenames remain visible even when absent from the current catalog, and generation still validates installed files. Catalog arrays and dropdown option elements are reused across prompt edits; disabling the chain/slot or closing the LoRA accordion unmounts its controls without deleting selected files, strengths or enabled states.
- **Spectrum**, **Realtime preview** and **RTX upscaler** have explicit switches. Spectrum and RTX are additions to the supplied graph and default **off**; realtime preview defaults **on**, using the supplied 1024 px / JPEG 80 / 500 frames / 6 FPS settings. Disabling a feature removes its node and reconnects the graph; it does not merely hide its output. Spectrum uses the installed node's baseline settings. RTX runs after video decoding, before CreateVideo; scale 1-4 and quality are selectable, defaulting to 2x / ULTRA when enabled. RTX requires compatible NVIDIA hardware/runtime.
- References are optional, with an enforced maximum of **6 images, 2 videos and 2 standalone audio files**, including on Library/composer transfers. A ReferencePack adapter loads uploaded multimodal files into the native H3 sockets; plain prompts bypass it. No references are silently dropped to fit a destination.
- All three H3 renderers have separate persistent drafts, render/transcription settings, previews and results. **Start from scratch** and **Reset settings only** affect only the selected workflow. Hidden running panels retain their own jobs.
- Animated sampling previews are released when a generation finishes, fails or is cancelled, rather than continuing to decode beside the final result. Completed videos request `preload="metadata"` rather than automatic full preload; the browser/container may still require additional bytes. The final output and already-saved intermediate links remain available. Prompt/settings edits are for the next run; ComfyUI schema validation is explicit or part of starting a generation, not a background operation on every keystroke. The separate Prompt Generator also reuses its model filtering/options when only an H3 draft changes.
- Video Prompt Generator and Library prompt actions offer all three renderers as destinations, including for old saves. Loading into the same variant restores its saved render options; switching variants retains prompt/references/aspect/duration/soundtrack selection, including reference enable/source-soundtrack controls, and explicitly loads destination model/sampling defaults. Original Library items are never rewritten.
- Original soundtrack mode requires the **original WAV lock** in Ultrafast: the existing local mux preserves the selected excerpt and trims surplus video. Native SaveVideo has no VHS `trim_to_audio` switch. Reference/generated audio remains available without locking.
- **Check workflow** validates the installed schema and selected files without rendering. Ultrafast additionally requires `BasicScheduler`, `MiniMaxH3SigmaShift`, `ModelAttentionBackend`, `LTX_lora_loader`, `CreateVideo` and `SaveVideo`; Spectrum, RTX and KJ preview nodes are required only when enabled. Node availability does not guarantee adequate VRAM or successful rendering.

Regression checks: `node --test services/minimaxH3UltrafastWorkflow.test.mjs services/minimaxH3Service.test.mjs components/VideoWorkspace.test.mjs services/videoPromptLibrary.test.mjs`.

## MiniMax Advanced

- Adapted from the supplied full Advanced workflow and its API export. **FL2V** is the default: image slot 1 is always the first frame, and slot 2 is always the last frame, even when the first is disabled. Either frame is optional. **REF2V** enables the multimodal reference path, with up to **3 images / 1 video / 2 standalone audio files**. Unsupported enabled references in FL2V cause an explicit error asking you to disable them or switch to REF2V; they are never silently ignored. A locked original soundtrack can still be used as output audio without becoming FL2V conditioning.
- Source sampling defaults are retained: **4 steps**, `seeds_2`, **BasicScheduler beta / denoise 1**, 0.3 MP, 4:3, 3 seconds, INT8 H3 video VAE, and 24 FPS. The screenshot's switches initialize **H3 latent upscale, Turbo LoRA chain, ComfyAttn, VRAM Clear and realtime preview on**; **LTX Refine, RTX, Boost, interpolation and image noise off**. The six individual H3 LoRAs start disabled. Turbo controls the source Power LoRA Loader chain, not an additional invented model; Boost groups Sol attention, sigma shift and feed-forward chunking.
- Mode/switches sit above the workspace. Basic and optional settings are single-level sibling accordions on the left; prompt/references are highlighted on the right, above generation/output, and come first on narrow screens. There are no nested option accordions. Disabling a feature hides its controls without deleting their values, including latent upscale, refinement, RTX, Boost, preview, LoRAs and image noise. LTX attention/LoRA controls also hide when their own switches are off.
- Advanced loads installed schemas/model lists on opening; model/encoder/VAE/LoRA fields use selectable menus, including before the catalog has loaded. Refresh remains available, and a failed request is shown explicitly. Closed optional accordions do not mount their large model menus, keeping prompt editing lightweight. Live schema choices and numerical bounds are used when available.
- H3 latent upscale defaults to **1.25x / align 32** and supports multiplier, target dimensions and megapixels, with model/device/precision/chunking controls, a separate seed and sampler, and editable second-pass sigmas (`0.9035, 0.6316, 0.3158, 0.0000`).
- LTX refinement exposes the resolved parent workflow's diffusion model, text encoder, dual VAEs, optional LoRA and attention, positive/negative prompts, preprocessing, anchoring batch/strength/bypass, latent-upscale model, seed, sampler, guidance, sigmas and tiled-decode controls. Defaults include the supplied LTX 2.5 models, seed 42, `lcm`, CFG 1 and sigmas `0.5, 0.3, 0.1, 0.0`. It uses the actual incoming frame count/FPS and retains H3 audio through the LTX audio VAE rather than substituting sampled LTX audio.
- The default **LTX refine LoRA** is `LTX2_camera_control\ltx-2.5-22b-ic-lora-refine-details-1.0.safetensors`, at the existing **0.6** strength. Choose another installed file under **LTX Refine · all options → LTX refine LoRA → lora_name**, or disable **LTX refine LoRA**. Existing drafts and Library setups retain their saved choice; the new default applies to fresh/reset settings and Library-video finishing presets.
- **LTX decode:** new Advanced defaults match Director's tiled settings: spatial tile **256**, spatial overlap **64**, temporal size **64**, temporal overlap **4**. Existing drafts/Library settings are preserved. Open **LTX Refine · all options** and choose **Use LTX Director decode settings** to apply these four fields and tiled mode without resetting your prompt or models. **Use low-VRAM decode settings (more passes)** retains the earlier 256/32/16/4 option: smaller temporal chunks can reduce peak memory but multiply passes and be slower. Neither preset is benchmarked or guaranteed to fit 8 GB.
- **LTX decode mode** selects `VAEDecodeTiled` or standard `VAEDecode`; tiled remains the default for older settings without a mode. Standard hides, but retains, tiled parameters and has higher peak-VRAM/OOM risk at Advanced resolutions. The stage ID, output ordering and intermediate saves remain unchanged. This is not the same workload as Director: Advanced encodes full incoming H3 frames and applies the source LTX latent upsampler **2x**, roughly quadrupling spatial pixels before final RTX. Director's normal half-resolution guide is upsampled back to its target. Prior H3 latent upscale and interpolation can further increase Advanced's spatial/frame workload. No real-render timing comparison has been made.
- **Stage order**, above the workspace in **Advanced mode & switches**, selects **LTX refine -> H3 latent upscale** or **H3 latent upscale -> LTX refine**. New projects default to LTX-first; older saved drafts/setups without this field retain latent-first. Stage on/off defaults are unchanged. In LTX-first mode, decoded LTX frames are re-encoded with the **H3 video VAE**, then passed through the existing H3 latent upscaler and second-pass sampler. LTX latents are never connected directly to the incompatible H3 upscaler. This adds an encode and can require reloading the H3 model; it is not a free image resize or a guaranteed speed/VRAM improvement. RTX remains **last** in either order, defaulting to **2x / ULTRA**, with multiplier and target-dimension modes. Final output remains node `119`.
- **Save intermediate videos · ON / OFF** is a prominent button in the **Video saving** card directly under the MiniMax Advanced heading, outside every accordion. It defaults **on**, including older Advanced drafts that predate this switch, and stays visible with every options accordion closed. Changes during generation apply to the next job. With latent upscale, LTX and RTX enabled, ComfyUI writes **FirstPass**, **LatentUpscale**, **LTX** and **Final_RTX** files in the selected stage order, with distinct suffixes. Only active stages are saved; the last active stage is saved once through node `119`, not duplicated as another checkpoint. Interpolation runs before LTX, after the early H3 latent stage when latent-first is selected. H3 checkpoints before interpolation use the selected output FPS; subsequent stages use interpolation's target FPS.
- Checkpoints are execution dependencies of downstream image/latent processing through the installed **Impact Pack Execution Order Controller**, rather than unrelated output branches that might run only at the end. First-pass saving adds a separate H3 video/audio decode only when latent upscale follows it; later checkpoints reuse already decoded frames. This adds decoding/encoding time, disk use and potentially RAM/VRAM pressure, especially with cached tensors. Turn the switch **off** for the previous final-only graph, which removes every checkpoint saver, ordering controller and extra first-pass decode. No GPU memory benchmark is implied.
- All stage files use the selected output encoder/audio controls and the global **Save output on ComfyUI** destination: keep it **on** for durable output files; **off** writes temporary server files. Selected original audio is retained; only the final output receives the app's local original-WAV lock/mux. Saved checkpoint links appear under **Saved intermediate videos**, including after a later stage fails, as soon as ComfyUI returns their output metadata. Cached links are recovered from job history. These links refer to server files; **Save to Library** still copies only the final output, not all checkpoint binaries.
- Filename prefixes can contain `%date:yyyy-MM-dd%`, expanded to the local date when building the submitted/exported graph. For example, `MrWeaz/%date:yyyy-MM-dd%/Advanced_` becomes `MrWeaz/2026-10-21/Advanced_`. ComfyUI's browser normally expands this template, but direct API jobs do not; sending it literally creates an invalid Windows directory because it contains a colon. This also fixes existing saved setups without resetting or rewriting their prefixes. Other or incomplete date templates are rejected before rendering. Normal H3 and Ultrafast use the same resolution.
- The supplied graph's final VRAM-clear node referenced an obsolete bypassed decode through `image_pass`, while its execution dependency used the real tiled decode. The exported API graph lost that stale image input but the saver still consumed its image output. Advanced reconnects `image_pass` to the actual decoded images and follows that image output into RTX/final saving. This is a graph-level diagnosis and repair, not a claim that a GPU render was reproduced.
- Optional RIFE interpolation retains its source position before LTX. Its target FPS is propagated to both LTX conditioning and final output to avoid slowed playback. Interpolation cannot be combined with the existing 24-FPS original-WAV lock; incompatible settings fail explicitly.
- Composer/Library transfers enforce Advanced's smaller limits before replacing any draft. Cross-variant loads use Advanced defaults, including FL2V: select REF2V for saved multimodal references when needed. **Save prompt to Library** preserves the selected mode, nested settings, switches, seeds and original/edited media. Each renderer's state and reset remain independent.
- **Check workflow** verifies installed active nodes, selected models and parameters without uploading or queueing. Optional nodes are required only when enabled. Neither schema checks nor mocked job tests establish GPU runtime, VRAM requirements or render quality.

Regression checks: `node --test services/minimaxH3AdvancedWorkflow.test.mjs services/minimaxH3Service.test.mjs services/videoPromptLibrary.test.mjs components/AdvancedH3Settings.test.mjs components/VideoWorkspace.test.mjs`.

### Finish an existing Library video

In Library, use a video's **Latent upscale** / **LTX refine** row buttons, or open its details and choose **Advanced · H3 latent upscale only** / **Advanced · LTX refine only**. This opens Advanced directly in **Finish an existing video** mode, with the selected stage enabled and RTX/interpolation off. The original Library item is never changed. You can enable additional stages and choose their order afterward, or select this input mode manually and upload a source video.

- Only enabled finishing stages run: no H3 first-pass sampler, FL2V conditioning or ReferencePack prompt rewriting. LTX-only does not load H3 models, H3 LoRAs or the H3 VAE. H3 latent-only uses the existing H3 VAE/upscaler/second-pass sampler. Its prompt remains editable; LTX-only instead presents the **LTX refine prompt** editor.
- Output FPS comes from the source video's loaded metadata, unless interpolation is enabled. **Keep source soundtrack** defaults on and passes the loaded audio through without LTX audio VAE re-encoding. The installed `/minimax_refpack/probe` endpoint checks uploaded sources for audio first; silent sources explicitly disable the audio connection. Probe failures stop before queueing rather than silently dropping a soundtrack. Turn soundtrack retention off to process without that probe/audio dependency. The separate original-WAV lock is unavailable in this mode.
- The complete source clip is loaded; dimensions are rounded to multiples of 32. VAE temporal compression can adjust the frame count: frame-exact duration preservation has not been verified. LTX retains its own internal **2x latent upsample**, even when H3 latent upscale is disabled. Long/high-resolution sources can exceed RAM/VRAM; no RTX 3070 render benchmark is implied.
- Intermediate saves include processed stages, not a redundant copy of the untouched source. Source files and finishing settings are included when saving the setup with **Save prompt to Library**, so it can reopen independently of the original preview URL.

## Timing and resolution

- Native H3 sampling is 24 fps, with frame counts rounded using the source expression to `5 mod 17`; the UI shows effective frames/duration and binary-megapixel resolution. Canvas dimensions must be divisible by 32. ReferencePack supports at most 60 seconds, not a promise of model quality/VRAM availability; native H3 describes a trained range of about 124–362 frames. Output FPS is independently configurable. All-frame previews are limited to 1024 frames; select fewer preview frames or disable preview for longer clips.

## Audio passages and waveform

- Each standalone audio reference has two theme-matched players, without the browser's native audio controls: **Generation audio** previews the current reference file; **Original track** keeps the full recording available, with custom play/pause, seek and volume controls, a spaced-bar waveform, timeline ticks, highlighted selection and playback cursor. Drag across the waveform to select a passage, click to seek, enter precise start/end seconds, or use **Set start/end here**. **Play selection** stops at the selection end; the original track's play button can play the whole recording. Playback pauses when the workspace is hidden.
- **Apply passage + H3 duration** creates a real PCM16 WAV excerpt locally and updates both the reference and H3 duration. Merely moving the selection does not change the submitted audio; unapplied edits are identified. **Next 3 s** (or the current selection length) advances directly from the previous end and applies the next excerpt in one click. The last passage is shortened to the remaining recording, never looped. Adjacent selections use the same rounded sample boundary, avoiding duplicated/skipped boundary samples.
- The full original, selected timestamps and edited WAV remain in the local draft, including across reloads. Prompt Library saves/restores also preserve them. **Restore original** restores the full audio reference without resetting H3 settings. Native H3 frame rounding/output FPS still determine actual video duration; a 3-second audio selection is not a promise of exactly 3 seconds of rendered video. Passages cannot exceed H3's 60-second limit. Audio decoding, waveform calculation and WAV export use system memory, not GPU VRAM; decoding failures are reported without replacing the current reference.

## Original soundtrack and passage lyrics

- **Soundtrack mode** is explicit in both prompt preparation and H3. The default **Reference / generated audio** retains the existing graph: input audio conditions REF2V, while `VAEDecodeAudio` decodes sampled, newly generated audio. That mode can change words, voices, melody or accompaniment.
- **Original track - do not regenerate audio** instead connects the selected standalone audio output of ReferencePack directly to VHS. The applied PCM WAV is the soundtrack; no generated audio is decoded or mixed in, including in live previews. H3's joint sampling/reference conditioning remains unchanged. This preserves the recording's performance, **not a guarantee of exact lip synchronization**. MP4 encodes audio to AAC, so this is not byte-identical/lossless WAV copying.
- Apply the intended passage first. Its duration must match H3 duration. Original-track output requires **H.264 MP4, native 24 FPS, no loops and no ping-pong**; incompatible settings report an error instead of silently changing them. Original mode rounds the native frame grid up to cover the entire audio, then forces VHS `trim_to_audio` on to remove the surplus; frame and audio-codec/container rounding can remain at the endpoint. Missing/disabled/deleted soundtrack references are rejected, never silently replaced.
- On each audio card, enable **Use exact lyrics / spoken words**, enter/review the text, or click **Transcribe current passage**. This manually sends **only the current edited audio file**, never the preserved full song, to Gemini or an audio-capable OpenRouter model using Connection Settings. It can incur API charges. Mammouth does not support audio in this integration. Transcription requests audible words only, without web lookup/song completion; review `[unclear]` markers and mistakes.
- **Next N s** never makes an automatic API request. Enabled lyrics for an earlier passage remain visible but are marked stale and block prompt/video generation until edited, confirmed for the new passage or transcribed again. Turning lyrics off restores reference-only prompting. Late transcription responses do not overwrite a newer passage.
- Edit the main prompt directly after changing an audio passage, or compose a new prompt in the separate Video Prompt Generator and explicitly send it to this workflow. There is no embedded prompt-generator or automatic prompt-refresh request in the rendering panel. Audio transcription remains optional and has its own provider/model settings.
- Original-track selection, lyrics and their passage stamp persist with local drafts and prompt Library snapshots, including transfers between preparation and H3.
- **Force original WAV soundtrack (lock)** adds a local final mux after ComfyUI finishes. It discards **all server audio** and maps only server video plus the currently applied PCM16 WAV, copying video without GPU use or video re-encoding. The player, download, last-frame extraction and Library save use this corrected local MP4. Save/download it before closing the app; the corrected file is not written back to ComfyUI. A failed/cancelled mux is an error, never a fallback to the server soundtrack.
- Selecting original mode enables the lock; existing original-mode drafts can enable it explicitly with the checkbox. Enabling chooses compatible H.264/24 FPS/no-loop output settings. Each editor keeps its own soundtrack choice; an explicit transfer copies the generator's selection into H3 along with its references. Later edits in either editor do not change the other. The lock survives Next, last-frame continuation, reloads and prompt Library snapshots. To return to generated-audio mode, uncheck the lock first. API workflow exports only contain the server graph; the extra local mux is performed by this application.
- The same waveform passage editor is available **before the first prompt** in Video Prompt Generator. Apply the desired excerpt there, then transcribe/compose the prompt. Unapplied partial selections block prompt/video generation, transcription and transfer rather than silently submitting an older/full track.

## Continue from the last output frame

- In the completed output of **Minimax REF2v H3**, **Ultrafast** and **MiniMax Advanced**, **Save last frame** downloads a full-resolution PNG and **Save last frame to Library** stores it under **Extracted Frames**. The default target is the exact last decoded frame. Scrub the video or **Frame selector (s)** to choose another position: the buttons become **Save this frame** / **Save this frame to Library**. **Last frame** returns to the end shortcut. Selected-time decoding keeps the frame at or before the cursor's presentation timestamp, without resizing or FPS conversion; it also supports variable-frame-rate video. Both actions use the corrected local video when original audio has been muxed. Extraction can be cancelled, and failures are shown without creating a Library item.
- Under a completed video, **Copy last frame to Picture 1** downloads that result and decodes forward to the actual last video frame, at full resolution. It overwrites one temporary PNG instead of retaining a reversed video in memory, so audio/container padding does not cause an approximate end-time capture. A decoding failure leaves Picture 1 unchanged.
- Existing Picture 1 keeps its reference identity, role and original image for **Restore original**; other references are untouched. If absent, Picture 1 is created. It is enabled for the next render. Then use **Next N s** on the original audio and generate the next clip. Nothing automatically starts another generation or overwrites the completed output. REF2V is reference conditioning, not a strict first-frame constraint: this assists continuity but cannot guarantee a seamless join. Image/animated-image outputs do not offer this video-frame action.

## Live preview and cancellation

- Job monitoring distinguishes base H3 sampling, latent-upscale sampling, LTX sampling, tiled decode, final RTX and final encoding/saving. Owned-job `executing`, `executed`, `execution_cached`, `progress` and newer `progress_state` events populate the stage log, cached/completed node count and node-local units. Entering a new node clears old sampler counts instead of relabeling everything "Sampling H3" or resetting overall progress to 20%.
- The execution panel shows elapsed job/stage time and time since the last job event, refreshed once a second. A stage with no reported unit count uses an indeterminate bar, not an invented percentage. After 2 minutes (120 seconds) without a new job event it warns to inspect ComfyUI logs/GPU activity; an open socket is not proof the GPU is advancing. Node counts are not time estimates, and image previews are not promised during every decode/refine stage.
- **Live preview** is available through KJ's client-targeted WebSocket API (JPEG, animated WebP or MP4), with independent preview resolution, quality, frame count, FPS, tiny/full VAE and audio controls. It is optional and can add decoding/VRAM cost. Sampling, preview, source soundtracks, conditioning VAEs, output audio, sigma extension, prompt display, LoRA chain and output-saving controls are independently adjustable where applicable. Disabling a branch removes/bypasses its nodes, rather than only hiding UI. Normal tab changes do not cancel a running H3 job. **Cancel** uses ComfyUI's atomic per-job `/api/jobs/{id}/cancel` endpoint, never a global interrupt; an older server without it reports a cancellation error and must be managed in ComfyUI. Closing/reloading the application does not stop an already submitted server job or resume its monitor.
- Prompt and settings stay editable while rendering, finalizing the original-audio mux or saving a completed result. A running generation uses its submitted snapshot; changes prepare the next generation and cannot overwrite the completed result's prompt/settings. Starting a second render remains blocked until the current one finishes.

## Execution and optional prompt rewriting

- Generation uploads enabled references to the configured ComfyUI server, displays the completed output and offers the exact executed API graph/prompt. Saved output remains on ComfyUI; disabling Save output uses its temporary folder. Browser playback depends on the selected output codec; image-sequence outputs remain in the server output folder. By default ReferencePack's provider is **none**, using your prompt unchanged except reference-token remapping. Without references or optional rewriting, the prompt connects directly to the native H3 conditioning node and bypasses ReferencePack. Optional server-side rewriting uses a local endpoint or `OPENROUTER_API_KEY` / `LLM_KEY` from the **ComfyUI server environment**, never a copied/embedded workflow key. Hosted rewriting may incur an additional charge.

## Save rendered output to Library

- **Save to Library** under the last completed H3 output copies the original result into **Library > Videos** (or Images for GIF/WebP/PNG output), with a thumbnail, actual seed, prompt, exact render settings and executed API graph. It stores a local binary asset, not the temporary ComfyUI URL, so playback/download and Library ZIP/Folder/Drive backups do not depend on the server file remaining available. Settings edited after the render do not change the saved result. Failed saves remain retryable; unavailable thumbnail codecs are explicitly reported and use a placeholder without discarding the original output. Library details expose the H3 settings/workflow; saving a result does not create a runnable input-reference snapshot. Image-sequence formats save only the file returned by ComfyUI, not the whole server-side sequence.

## Save and reopen generation prompts

- **Save prompt to Library** in **Prompt & references** saves the current free-form prompt, all original and edited image/video/audio reference files, stable slots, roles, passage timestamps/lyrics and the complete H3 configuration (including seed, models, LoRAs and disabled reference controls) to **Library > Prompts**. No render or LLM request is required. This saves a new item, never replaces an existing saved prompt, and keeps editing available while saving. Apply pending audio changes first.
- **Open in Minimax REF2v H3** loads both new generation setups and older Video Prompt Generator Library items directly into this renderer, not into the prompt generator. The independent prompt composer remains unchanged. Replacing an existing H3 draft requires confirmation.
- The renderer is selected immediately, including while references load or if restoration fails. A failed load leaves the current H3 draft intact and reports the affected filename rather than leaving the user in Video Prompt Generator.
- Reference restoration reads persistent Library binary assets directly rather than fetching temporary `blob:` preview URLs, which can expire between sessions. For older items without a usable binary, recovery checks the persisted video workspace for the exact reference ID, filename, MIME type and modification timestamp. A recovery notice asks you to save a new durable setup. No thumbnail, unrelated file or empty reference is silently substituted; unavailable files still require a backup or the original upload.
- Compatibility is handled when loading, without rewriting, deleting or batch-converting old Library items. Older prompt-generation snapshots retain every stored original/edited reference and their aspect/duration/soundtrack choices. Since they did not store H3 models/sampling settings, a visible notice identifies the use of default H3 settings. Review these before rendering and save a new generation setup to retain your chosen settings.
- Older `wan-video` text-only prompt items also open here; any stored source/start/end images are recovered as references, without claiming first/last-frame interpolation. Files not present in an old save cannot be recreated. Missing reference assets or unsupported metadata versions report an error and leave both the original Library item and current H3 draft unchanged.
- Generation setups use the existing prompt-reference binary asset format, so Library archives, Library Folder projects and Drive backups include their reference files and render settings. Rendered-output saves remain separate and are not retroactively converted into reference-input snapshots.
