## Image and character workflows

- Text-to-image and image-to-image generation through Mammouth AI or ComfyUI.
- Local workflows for SD 1.5, SDXL, FLUX2 Simple, Qwen Image, Qwen Edit, Z-Image, MOSS Image, MOSS PHOTO, KREA2 Simple, KREA2 RAW, and face detailing.
- Qwen image-to-image editing with multiple source references passed independently to ComfyUI.
- FLUX2 Edit with a primary source image and role-based references for identity, outfit, background, pose, style, or custom instructions.
- **Scene Variation > Clothes Switcher** is a separate, faithful Klein 9B outfit-editing workflow with original/depth/Canny reference latents, three LoRAs, both preprocessing previews and a final before/after comparison. See [Clothes Switcher](scene-variation.md#clothes-switcher) for exact defaults and controls.
- Import the FLUX2 source and reference images from the Library, retain saved Library prompts, and generate role-aware reference hints through Mammouth AI. Pose references are analyzed directly for accurate pose guidance.
- Adjustable checkpoints, UNets, CLIP models, VAEs, samplers, schedulers, seeds, dimensions, and LoRA chains.
- Refine mode with source-image denoise control.
- Character generation with pose, clothing, background, and multi-angle controls.
- Character now defaults to FLUX2 with `flux2\flux2Klein9BInt8_v10.safetensors`, `qwen38BFluxKlein9BTE_38b.safetensors`, and `flux2-vae.safetensors`. Existing saved presets retain their selected models. **Load FLUX2 angle workflow** applies the supplied Klein multi-view prompts with this 9B model/CLIP pair, 4 steps, CFG 1, Euler, 1 MP, no LoRAs or CacheDiT, and no pose reference. It replaces the output settings but retains the source image and current seed. The first six outputs are front three-quarter, side profile, rear, rear three-quarter, high angle, and low angle; the seventh is a disabled close-up template requiring its bracketed angle/detail fields to be completed. The eighth slot stays disabled.
- Each reference output uses an editable **Full workflow prompt**, sent verbatim to CLIP unless **Preserve original background with new perspective** is checked. This opt-in checkbox replaces the background clause with a request to preserve the original location and objects as viewed from the requested angle. It also works with structured prompts and takes priority over custom backgrounds and background reference images. Stored prompts remain untouched, so unchecking restores their original wording. The reference prompts otherwise request photorealism and a neutral compositing background; they are not Scene Variation's source-style-preserving prompts. Switch an output back to **Angle / pose / expression** to use the original controls. Empty full prompts and unresolved close-up placeholders are rejected before upload or sampling. The seven stored texts match the supplied JSON; the six complete graphs were compared with the original 4B settings and matched seeds, ignoring node IDs, metadata and save filenames. Current defaults intentionally use 9B instead. Regression checks: `node --test services/characterAnglesWorkflow.test.mjs services/sceneVariationService.test.mjs`.
- **Return to standard FLUX2** exits full-prompt mode for all Character outputs at once, including disabled outputs and incomplete close-up templates. It removes the full prompt overrides and restores the angle/pose/expression controls while retaining their values, enabled outputs, models, sampling, seed, and background-perspective checkbox. It does not restore a historical snapshot from before loading the reference workflow. The button is unavailable while generating.
- SAM3.1-guided Swap Anything with destination/donor images, editable target regions, optional LoRAs, and FLUX2 sampling.
- Inpainting, composition, generated masks, and reusable source elements.
- Exportable ComfyUI workflows and reusable generation presets.
- **Cancel Generation** remains visible during progressive ComfyUI Character generation (FLUX2, Qwen and Qwen 2.1 Create Character). It interrupts the active ComfyUI job and prevents remaining outputs from starting, including cancellation during source uploads or preparation. Completed images remain available; cancellation does not open a generation-error modal.
- **Character > QWEN 2.1 > Create Character** uses direct Qwen edit prompts for eight independently enabled views: requested camera/framing changes come first, followed by pose/expression and concise identity preservation. It does not reuse the long FLUX2 prompt or its saved full-prompt overrides. An explicit output pose takes priority over a pose-reference image; otherwise the reference supplies the pose. The original-background instructions retain the physical location while allowing its projection to change with the camera. Source, clothing, background and pose references are encoded separately in their actual order. **Output Size** and **Orientation** control the independent empty latent; the unrelated general Aspect Ratio selector is hidden. Submitted eight-view graphs and real ComfyUI history have been checked for prompt/encoder/sampler links, not for visual angle compliance. Start a new generation to use updated prompts; existing results and their recorded final prompt stay unchanged.
- **Turbo (Viggle)** in Create Character is off by default. Enabling it switches the full sampling graph to the native Viggle I2I Turbo chain: mandatory Viggle LoRA, ModelSamplingFlux, BasicScheduler at 4 steps, ExtendIntermediateSigmas with 3 subdivisions, BasicGuider and SamplerCustomAdvanced. It keeps the eight output prompts, up to four ordered references and independent output canvas; it is not a LoRA-only modification of KSampler. Turbo sampling values are fixed while enabled, and disabling it restores the unchanged normal settings. Required nodes and the Viggle LoRA are checked before upload. The toggle is unavailable during generation; Cancel Generation still works.
- ComfyUI Character's eight output controls are in the wide right column below Generate. Each output can be expanded/collapsed; **Collapse all outputs** / **Expand all outputs** keeps saved values and enabled selections unchanged. Camera, pose and expression fields share a row on desktop and stack on mobile. Background and reference controls remain on the left. In Qwen Create Character, **Green Screen** explicitly requests replacement of the entire scenery with uniform chroma-key green, overriding stale custom/background-preservation settings. Selecting a background clears the preservation checkbox; Green Screen disables it. This instruction is verified in all eight normal/Turbo queue prompts, not in a new GPU render.

## Blazing Fast character and Style Gallery

Open **Character > ComfyUI > FLUX2 > Blazing Fast character**. The existing **Character Angles** tab is unchanged. This integration starts from the supplied `00-blazingFastCharacter_v11_API.json`; the companion visual JSON was inspected for subgraph and passthrough wiring, not used as an older Character preset.

- Reference, models, sampling, pose count and active pose controls are on the left; editing prompt, style, additional LoRAs and generation are on the right.
- **Number of Blazing poses** selects 1–6 (six by default), generating the first N configured poses. The source pipeline is retained: source-image vision description; initial FLUX2 edit; later views conditioned on the **first edited image**, not on each other. With fewer than six, unused branches are removed from the submitted graph: there is no collage, comparison or final collage caption. Six completed views allow the original 3-column/2-row collage, original-versus-collage comparison and vision-generated reference description.
- Each view has editable camera/framing, pose and facial expression dropdowns with the existing Character presets and a **Custom** text option. All six stored pose configurations default to **Same as reference**: no forced close-up, back view, posture or expression is inserted from the original example workflow. Each small dice button randomizes that view's angle, pose and expression; **Randomize all poses** randomizes the selected N poses. **Reset poses to reference** clears all eighteen fields. Reducing the count retains unused pose settings. Saved drafts/presets retain their previous selections until explicitly changed.
- **Background** uses a standard preset dropdown: same background, remove background, black, white, gray, green screen, natural studio, or custom text. The default keeps the reference background. Background instructions reach every selected pose's generation prompt.
- **Style LoRA strength** overrides the gallery's strength locally for every selected Blazing Fast pose, including a strength of zero. It is saved with the draft and Library settings without editing the shared style. Selecting another style or **Use gallery strength** removes the local override. Prompt-only styles have no LoRA strength control.
- **Prompt preview — current settings** shows the exact prompt composition, marks whether the editing prompt/style trigger/style text are included, and exposes every selected pose's instructions. The identity is explicitly a placeholder before vision analysis. **Latest run — actual initial prompt** shows the executed initial prompt separately, so editing settings after generation does not relabel an old result. Every pose receives the global editing prompt plus separately labelled camera, expression and body-pose instructions. Later poses still reference the first edited image. Explicit changes take priority over reference posture/expression; styles control visual rendering rather than action. T-pose expands to an upright full-body stance with straight arms extended sideways at shoulder height.
- Identity analysis is restricted to stable visible identity traits, excluding expression, posture, held objects, framing, scene and style. This scope is also appended to saved/custom identity systems so older drafts do not reintroduce conflicting instructions. This improves prompt consistency, not a guarantee of visual adherence; sampling, LoRA strength and reference conditioning still affect results. No sampling defaults or reference-image connections are changed by this prompt revision.
- API defaults: Klein 9B INT8, Qwen 3 8B FLUX2 encoder, FLUX2 VAE, Qwen3 VL 4B vision encoder, Euler, four steps, CFG 1, 1 MP, one shared seed. Model filenames are editable; the visual JSON's alternative model filenames do not silently override API defaults.
- **Blazing sampler** is a standard dropdown containing every sampler exposed by the connected ComfyUI `KSamplerSelect` node. No sampler-name subset is imposed. Style sampling overrides still take priority when enabled.
- The source's fixed Same Style/Pixar menu and example Moebius/desert prompt are replaced by the gallery selector and editable prompt/background. No style LoRA is enabled initially. No old Character prompt builder, DWPose, CacheDiT or photorealism instruction is injected.

The root **Gestionnaire de styles** tab contains the 27 supplied **FLUX2-9B** styles. Existing `FLUX2` style entries migrate to `FLUX2-9B` without changing IDs, links, prompts or manual settings. `FLUX2-4B` is a separate model category. Search/filter by model; create, edit, duplicate or delete styles in a modal editor; configure title, model, full LoRA path, strength, trigger, prompt/boosters, optional steps/CFG/sampler/megapixels and notes. Blank LoRA means a prompt-only style. Initial descriptive prompts use the supplied style titles; these are not claimed to be special LoRA triggers. Unknown triggers and “best settings” remain empty rather than invented. The MIGUNOV core triggers and boosters are kept separately.

Gallery cards offer **Petit**, **Moyen** and **Gros** sizes. Display preferences persist locally. Pagination at the top and bottom supports 12/24/48/96 styles per page, first/previous/next/last and direct page selection. Search/model changes reset the page, and only the current page's cards and previews are mounted. **Blazing Fast**, **Image Gen > ComfyUI > FLUX2 SIMPLE** (t2i) and **FLUX2 Edit** (i2i) choose styles through this searchable, paginated thumbnail modal, not a style listbox. Dialogs support keyboard focus containment, Escape and a Close button.

**KREA2 styles:** select **KREA2** in the root style manager to create LoRA-backed or prompt-only styles with the same editor, photos, sizes, pagination and library links. Installed choices accept the `KREA`/`KREA2` folders and compatible indexed LoRAs, including files categorized manually in My Library; explicit classifications take priority over folder names. Already-used LoRAs are hidden when creating a style. No KREA2 styles or trigger recommendations are invented.

For now, only **Image Gen > ComfyUI > KREA2 > SIMPLE KREA** has the KREA2 style picker; **KREA2 RAW** and **I2I Edit / Identity** retain their own workflows. SIMPLE KREA defaults to `krea2_turbo_fp8_scaled.safetensors`, with no additional Turbo distillation LoRA in slot 1. Slot 2's existing `snofs_krea_v1_nostrip.safetensors` is retained. Initial state, resets, workflow export, Library USE and prompt-import defaults agree; switching tabs preserves explicit saved model choices.

The style picker, prompt preview and a dedicated **Style LoRA (gallery)** card are in the **right-hand LoRA panel**, before the six additional slots. The card shows the full installed path, effective adjustable strength (including a clear zero-strength warning) and its independent activation. **Only Apply style sampling overrides stays on the left.** The **Enable additional LoRAs** switch controls the six additional slots, not the gallery style. Additional LoRAs stack with the style and can change its visual effect; disable them to isolate the style. The graph connects base model -> style LoRA -> additional LoRAs -> sampler, and duplicate style paths are removed from additional slots.

The selected style's trigger leads the actual generation prompt without rewriting your editable prompt. Optional KREA2 style sampling applies steps, CFG, sampler, scheduler and megapixels while preserving aspect ratio. The applied prompt is previewed and returned with the generated result for Library saving. Switching/clearing a style replaces its prompt and LoRA, keeps unrelated additional LoRAs, and refreshes local/remote LoRA prompt examples. My Library **USE** and the generator reset clear the active KREA2 style before applying their settings.

**Save sampling as style default** records the current editable steps, CFG (including zero), sampler and actual scheduler in the selected gallery style. It is available in the sampling panel for **SIMPLE KREA / FLUX2 SIMPLE**, in the style controls for **FLUX2 Edit**, and in **Blazing Fast** sampling. Only these four defaults are changed: prompts, triggers, LoRA path/strength, library link, notes, seed and resolution are kept. Saving merges into the latest stored gallery, preserving unrelated styles and edits, updates the active image-style sampling snapshot, and persists through reload and JSON export/import. A missing/deleted style must be saved/restored in the style manager first; invalid settings and storage failures are shown explicitly. Defaults apply when **Apply style sampling overrides** is enabled; saving does not change that checkbox. KREA2 records the selected scheduler (for example `bong_tangent`).

**Optional style scheduler:** the style editor offers installed scheduler presets and custom text. Leave it empty (**Keep workflow scheduler**) to retain the generator's existing scheduling. For FLUX2, `flux2` explicitly keeps the native automatic **Flux2Scheduler**. Any other selected scheduler, with style sampling overrides enabled, replaces each active FLUX2 scheduler with **BasicScheduler**, using the exact model feeding its sampler (including style/additional LoRAs and optimizers), the configured steps and full denoise (`1`). This works in **FLUX2 SIMPLE/Edit 9B/4B** and all active **Blazing Fast** poses, including pruned partial-pose workflows. Disabling style sampling overrides restores the original workflow; model, prompts, seed, references and sampler connections are unchanged. Saving sampling while an override is active keeps that forced scheduler rather than resetting it to automatic. A forced scheduler changes the sigma schedule and may change results; unavailable nodes/scheduler choices fail explicitly during ComfyUI validation.

The style editor uses a two-column layout on desktop: an uncropped, aspect-ratio-preserving library photo and readable recommendations on the left; identity, LoRA selection, prompts/triggers, optional sampling and notes on the right. The preview sidebar stays visible while scrolling, and the Save/Close/Duplicate/Delete action bar stays accessible at the bottom. Technical metadata is collapsed by default. On smaller screens the columns stack. Gallery thumbnails retain their existing cropped card presentation.

When creating a new style, both library and installed LoRA selectors hide files already used by a saved style for the same model. Matching respects paths, unique filenames and library links; ambiguous filenames are not guessed. Editing an existing style retains the full compatible choices. Prompt-only styles and the explicit Duplicate action remain supported.

**My Library integration:** styles automatically match compatible indexed LoRAs by exact ComfyUI path or a unique filename. **Choose library LoRA** can create a style from an already indexed LoRA; **Link this LoRA** or **Link matching styles** saves stable path/hash references. Ambiguous matches require an explicit choice. Linked styles show the library preview image and provide **Open in My Library**, which navigates to the exact model card. The installed-LoRA and sampler pickers use standard preset dropdowns with a custom-text option, not large datalists.

Only missing trigger, steps, CFG and sampler fields are filled from existing library usage metadata. Manual values (including CFG zero), prompt text and LoRA strength are preserved. The editor shows inherited values as placeholders and lists which fields are supplied automatically; Blazing Fast resolves those same values for prompt previews, checks, API export and generation snapshots. Unknown sampler recommendations are reported rather than guessed, and absent recommendations do not introduce defaults. Library scheduler/guidance metadata is not inherited automatically; forcing a scheduler requires an explicit style setting. Inventory reads are shared and reuse the stored inventory; when it is empty, Electron uses its existing fast inventory initialization rather than a full hash scan. Native My Library data and local preview files require the Electron desktop app; browser-only use retains ComfyUI/manual style editing.

The gallery is stored locally, supports JSON import/export and updates compatible selectors immediately. **No style** removes the gallery style but keeps independently enabled additional LoRAs. Up to four additional LoRAs follow the Blazing Fast style LoRA. Their selectors use the same dropdown as other generators, filtering compatible `FLUX2`, `flux2-9b` and `flux2-4b` paths and library categories. As requested, unclassified LoRAs in the legacy `FLUX2` folder default to 9B unless explicit 4B metadata or naming identifies otherwise. New 9B/4B categories remain separate; no file is automatically moved. The filtered options are memoized rather than rendering the entire LoRA inventory as text suggestions. Saved selections outside the current list remain visible and unchanged, but cannot be selected again after replacement. Choosing **None** disables that slot; empty slots cannot be enabled. Installed paths are resolved by exact path or unique basename (including filenames supplied without `.safetensors`); missing or ambiguous paths block generation, never silently disable a style. Optional style sampling overrides can be turned off without changing the user's sampling values.

**Style trigger ordering:** in **SIMPLE KREA**, **FLUX2 SIMPLE**, **FLUX2 Edit** (9B/4B) and every **Blazing Fast** pose, the style's trigger is the first line of the actual positive prompt, ahead of editing/reference instructions or the generated identity description. Existing whole-token copies in the editable prompt/style boosters are moved to this prefix; unrelated substrings and generated reference instructions are preserved. Style boosters remain in the prompt body. The editable user prompt and shared style record are not rewritten. Preview, workflow export, generation and saved actual prompts use this ordering. Blank triggers and no-style generation add no prefix.

**FLUX2 i2i styles:** the picker follows the selected Klein model's explicit 9B/4B variant; an unidentified model (including FLUX2 Dev) is not assumed to be Klein 9B. Selecting a style snapshots its resolved library metadata into the generation options. Reselect it to refresh recommendations. Its trigger leads the complete prompt, and its style text supplements the editing instructions without replacing reference-role instructions or the user's prompt. A separate style LoRA precedes the two additional LoRAs and CacheDiT; its local strength accepts zero. **Apply style sampling overrides** optionally applies steps/CFG/sampler/megapixels without modifying manual generator settings. The preview exposes the composed text. Style selections are stored with Library options, and the saved final prompt comes from the submitted graph. Reset removes the style. Cross-variant styles and explicitly incompatible LoRAs are rejected before queue submission. Other tools using the shared FLUX2 edit builder do not inherit this image-generator style implicitly.

**FLUX2 t2i styles:** **FLUX2 SIMPLE** offers the same thumbnail modal, with a separate selection and strength from i2i. The style LoRA runs before the six existing additional LoRA slots and remains active independently of their master switch. Optional style sampling applies steps/CFG/sampler; megapixels scales the selected aspect ratio to dimensions rounded to multiples of 16. The enriched prompt is used by generation, workflow export and Library results. Clearing/resetting the style restores normal generator settings. In both image modes, **Local prompts** appears automatically for selected style/additional LoRAs with indexed, locally saved prompt examples (Electron required). Duplicate LoRA paths produce one button. **Use prompt** updates the correct t2i/i2i prompt without replacing the selected style; already included style triggers/text are not appended a second time. Local prompt lookup errors are reported rather than treated as absent examples.

**Changing image styles:** selecting or clearing a gallery style removes additional-slot copies of the previous and newly selected style LoRAs (case/slash insensitive), with a notice. Independent LoRAs and the user's prompt remain unchanged. Workflow generation also prevents loading the selected style twice when an older preset contains it in an additional slot. The next generation uses the new style; previously generated images are not restyled automatically. Style instructions written directly into the user's prompt remain active and can be edited separately. Failed style selections keep the picker open and display the error instead of silently closing it.

**Prompt-example buttons:** indexed active style/additional LoRAs show **Local prompts** when examples are saved locally, otherwise **Find prompt examples**, using the same Civitai/CivArchive lookup as Library **USE**. Lookup runs only when clicked; **Save all locally** then changes the button to **Local prompts**. FLUX2 t2i/i2i discard a previous **USE** source when its LoRA/base model is no longer active, including after changing or clearing the style. An old style still intentionally enabled in an additional slot keeps its own button. The modal identifies the source actually opened, and late responses from obsolete requests cannot replace the current examples. Changing styles does not delete saved prompt files. Electron and an indexed library entry are required for local/remote model prompt lookup.

**FLUX2 i2i layout:** model/CLIP/VAE, core sampling options, the editing prompt and its prompt-example buttons stay on the left. The right workspace contains the style selector and strength, source image/library picker, up to three role-based references and their descriptions/library prompts, and both visible additional LoRA slots. Only accelerator options remain behind **Advanced**. The layout stacks on narrow screens and retains the same generation, Library, reference and export handlers.

**Image-generator defaults:** both FLUX2 SIMPLE (t2i) and FLUX2 Edit (i2i) default/reset to `flux2\flux2Klein9BInt8_v10.safetensors`, paired with `qwen38BFluxKlein9BTE_38b.safetensors` and `flux2-vae.safetensors`. Catalog refresh no longer forces the old 4B CLIP onto a 9B model. Explicitly saved model choices and custom CLIP/VAE selections remain supported; use Reset to apply the new defaults to an existing configuration. Selecting a 4B model still selects its matching default encoder when using a standard encoder.

**Generate N poses** submits one graph. Live step/image previews and completed outputs are shown while it runs. **Cancel** remains available during preparation, queueing, sampling, captioning and output downloads/saving; cancellation targets only the owned job, never a global queue interrupt. A server without targeted job cancellation reports the failure explicitly. After cancellation or execution failure, completed image files are recovered from the owned job's history and live events. Their download and Library buttons become available again; unfinished sampling previews are not treated as completed files. Recovery errors are explicit and do not discard already received files. Cancellation cannot roll back a Library write already in progress.

Successful results are automatically stored under **Library > Character**, with linked TXT entries under **Library > Prompt**: N images for 1–5 poses, or eight images for six poses including collage/comparison. Cancelled or failed runs can be saved manually, one image at a time or all available images with **Save / retry Library**, without duplicate image/text pairs. **Download N images + TXT (ZIP)** uses the actual available count. Every saved image retains its source, exact settings, workflow, seed and completion outcome. The final caption, when available, is the source workflow's generated **whole-sheet reference description**, not independent per-image vision captions. Each TXT includes available vision identity and actual generation instructions; absent final captions are explicitly marked as unavailable, never fabricated. Library details expose the caption, TXT download and **Open in Blazing Fast character**; restoring a historical style does not overwrite a changed gallery style.

Draft settings and input image persist locally. Library media uses the existing IndexedDB, archive/folder and Drive asset mechanisms. No LoRAs or model weights are downloaded automatically. See [dependencies](../reference/comfyui-workflows.md#blazing-fast-character).

## MOSS PHOTO

Open **Image Gen > ComfyUI > MOSS > MOSS PHOTO**. **MOSS Image** remains a separate, unchanged workflow, including its 1280 px limit and optional image refinement. PHOTO uses the supplied compact v7 workflow, reconstructing branches absent from its API export using the normal workflow.

### Quick start

1. Connect ComfyUI and check the [PHOTO dependencies](../reference/comfyui-workflows.md#moss-photo). Models and custom nodes are not bundled with the app.
2. Leave **AI prompt writer** enabled, enter an idea in the active row and choose a look. **Your own style** opens an editable style accordion; the experimental IR look opens its infrared parameters.
3. Keep the default **1024 x 768 / 25 steps / batch 1** for an initial run. Open **Image size + focal length** to change the canvas or lens, and **Models & LoRAs** to select installed weights.
4. Enable only the finishing stages you need. Their parameter accordions appear when enabled; closed model/parameter accordions do not mount their large menus until opened.
5. Generate, inspect the final image and **Final Prompt Used**, then save the result to the Library or save a parameter preset for reuse.

| Setting | MOSS Image | MOSS PHOTO |
| --- | --- | --- |
| Default canvas | 1280 x 848 | 1024 x 768 |
| Default steps | 10 | 25 |
| Size controls | Portrait/landscape/square presets, max 1280 px per side | Eleven ratios, ten long-side sizes, custom canvas and lens ratios |
| Prompt path | Direct positive/negative prompts | Local AI idea expansion or an own-prompt row without rewriting |
| Optional image source | Refine Image, with source proportions and denoise | Text-to-image workflow; no source-image refinement input |
| Finishing | Existing MOSS sampling/refinement controls | Optional second pass, IR, face/hand fixes, SeedVR2 and JPEG |

### Controls and conditional accordions

- **Style Gallery - MOSS (additional style)** sits between **Look, people, quality & extras** and **Image size + focal length**. The shared **MOSS** category serves both **MOSS Image** (beside its prompt) and **MOSS PHOTO**, with prompt-only or LoRA styles, My Library links/previews and the same filtered picker. PHOTO styles are additive: the existing Look, own-style text, people/flash, lens rules, AI writer/manual rows and finishing are retained. The trigger is prefixed and boosters appended after the final photo prompt has been composed, so the AI writer cannot rewrite away the gallery style. The infrared positive branch receives the same style complement. Choosing No style removes only the gallery contribution.
- The dedicated gallery LoRA is shown with its full installed path and independent strength, before the existing LoRA stack. Duplicate gallery paths are removed from additional slots; unrelated LoRAs remain. Optional **Apply style sampling overrides** applies only steps/CFG/sampler/scheduler to MOSS Image or PHOTO's primary render, never its writer, second pass, IR sampling, repair/finishing parameters, image size, aspect ratio or refinement denoise. **Save sampling as style default** saves those four editable sampling controls back to the shared style. Style selections/strength/override flags are retained independently for Image/PHOTO, included in presets/exports and cleared by the corresponding Restore defaults action. My Library model/LoRA USE clears the active gallery style without replacing PHOTO's Look.
- **Your idea** supports adding/removing rows, one active radio selection, or explicitly combining enabled ideas into one prompt. The primary idea also receives Library/Civitai prompt imports. Personal example prompts from the supplied workflow are not bundled as defaults.
- **AI prompt writer** uses the local Qwen writer model. Turning it off opens independent own-prompt rows; one selected row is used. **Add look + lens text** appends the source look/lens/flash/ordinary-person wording. Turn it off to send the selected positive prompt without AI rewriting or photo-look additions; an explicitly selected gallery style still complements it. Choose No style as well for an unchanged positive prompt. Negative conditioning and photographic postprocessing still apply. The unused writer model and text-generation nodes are omitted entirely.
- Choose exactly one of Clean, Your own style, Kodachrome, Cheap iPhone, Aerochrome prompt, experimental Aerochrome IR, Portra, Tri-X, CineStill, Polaroid or LomoChrome Purple. Your own style and IR expose their conditional accordions. Flash and ordinary-person wording are independent switches; ethnicity/subject mode selects Caucasian, Asian, As in my idea or No people.
- **Quality** defaults to 25 steps and allows 1-50. Optional second pass, face fix, hand fix, SeedVR2 detail and JPEG crunch each reveal their parameter accordion when enabled. Execution order is first pass, optional second pass, optional IR, face fix, hand fix, SeedVR2/detail mix, sharpening, film grain, JPEG. Disabled branches are absent from the submitted graph and do not require their nodes/models.
- Polaroid bypasses sharpening, focal text and SeedVR2, retaining their saved settings for other looks. Tri-X forces monochrome film grain. Cheap iPhone honors `always_on_for_iphone` and its separate JPEG settings even when the general JPEG switch is off.
- **Image size + focal length** exposes all eleven ratios, custom ratio/resolution, ten long-side sizes (768-2560), batch size 1-64, snap 8-64, swap, ten focal choices, automatic lens ratios, fisheye type and full/short lens descriptions. XPan/Widelux force their horizontal panoramic ratios. Default output is **1024 x 768**, 4:3, snap 16, lens Off. The displayed aligned dimensions match the resolution node; unlike standard MOSS, PHOTO is not capped to 1280 px.
- Custom ratio terms accept whole numbers **1-99**; custom resolution sides accept whole numbers **64-8192 px**. Snap alignment uses multiples of 8 from 8 to 64 and rounds to the nearest grid value, with halfway values rounded up. For example, 1000 px at snap 16 becomes 1008 px. The displayed size and Generate summary use the effective lens ratio and aligned dimensions, not just the manually selected ratio. These input limits are not a guarantee that a large canvas will fit in GPU memory.
- **Models & LoRAs** contains diffusion model/dtype, text encoder/type, VAE, AI writer/type and four independent None/file LoRA slots with strengths. Live server menus supply installed choices. The source combined loader is split into equivalent standard loaders so disabling the writer genuinely avoids loading its model.
- **Sampling & finishing** and **Negative prompt, seed & output** retain the source advanced controls. Shared seed modes control the first pass and face/hand fixes; second-pass, IR, grain and SeedVR2 seed parameters remain independently editable, as in the source workflow.

### Presets, Library and output

PHOTO settings are retained independently when switching subtabs within the session and are included in presets, generated-image options and exported API workflows. Save a parameter preset to reuse a setup later. **Restore PHOTO workflow defaults** resets PHOTO options and its extra idea/own-prompt rows while retaining the shared primary idea and seed.

Library prompt imports update the primary idea in AI mode, or the selected own-prompt row with the writer off, without replacing models or sampling settings. Applying a MOSS model/LoRA from the inventory while PHOTO is active keeps the PHOTO subtab and its other settings; occupied LoRA slots are not silently replaced.

Run count times batch size determines the progressive output cards; only the final SaveImage output is collected. Standard ComfyUI JPEG/PNG binary previews are displayed when the server provides them. The final prompt reported by the writer is retained from execution output or history, including when ComfyUI reuses cached prompt-writing results.

Required packages, weights and optional dependencies are listed under [MOSS PHOTO dependencies](../reference/comfyui-workflows.md#moss-photo). Missing active nodes, model/LoRA choices and out-of-range server parameters fail explicitly before queueing. Nothing is installed or downloaded automatically by this integration.

### Validation and limitations

Integration validation on **2026-10-28** included a successful real ComfyUI render with the default PHOTO model, **25 steps and a 1024 x 768 saved image**, plus verification of the final prompt in the app. Automated checks cover branch wiring, seeds, batches, prompt imports, presets, subtab isolation and conditional controls; the existing H3 regression suite also passed. All looks and enabled extras were checked against the connected server's schemas. This does **not** mean every optional stage or combination received a separate GPU render or visual-quality assessment.

Run focused checks with `node --test services/mossPhotoWorkflow.test.mjs services/mossWorkflow.test.mjs`. To also preflight against your installed ComfyUI schemas without queueing images, use PowerShell:

## Importing Library prompts

In the **Image Generation** tab, **Import Library Prompt** opens a searchable text list of saved image prompts for every ComfyUI, Gemini and Mammouth model. Hover a row or focus it with the keyboard to preview its linked result, source image or generated preview thumbnail. An entry without an associated image remains selectable. Video prompts and generation presets are excluded.

Clicking a row replaces only the active positive prompt (or active cloud edit instruction). It does not load the entry's model, LoRAs, sampler, negative prompt, seed or other settings, and it preserves the saved text's formatting. Qwen 2.1 multi-image editing requires **Manual prompt** to be enabled first, so importing does not change that setting. Its manual textarea shows the stored text verbatim; the existing background-blending instruction is still added at generation when a background reference is active. Cloud inpainting's **Remove Area** task has no editable prompt; select Custom Prompt, Replace or Change Color before importing.

**MOSS Image** offers **Portrait / Landscape / Square** and valid resolution presets up to **1280 px per side**, replacing the separate width/height sliders. Its default is 1280 x 848; the other source workflow values are unchanged. The sampler's **Steps** control ranges from **1 to 50**, with the default unchanged at **10**. These defaults and the 1280 px cap do not apply to the separate [MOSS PHOTO](#moss-photo) subtab.

In MOSS options, enable **Refine Image (Image-to-Image)** to upload/drag a source or select it from the Library. **Refine denoise** controls how strongly it changes (0-1, default 0.5). The source is VAE-encoded instead of using an empty latent. Refinement preserves source proportions rather than using the T2I canvas, reducing only when needed to stay within 1280 px and aligning down to 16 pixels. The exact resulting size is displayed. Disabling refinement restores the unchanged T2I size and denoise; its uploaded source is not used.

## Generating a prompt from an image

In **MOSS > Refine Image**, upload or select a source image, then click **Generate Prompt from Image**. The reusable dialog previews that image and offers **SD 1.5**, **SDXL**, **Z-Image**, **Qwen 2.1** and **MOSS** prompt formats independently of the current image-generation model.

Choose **OpenRouter**, **Gemini**, **Mammouth** or **Local (Ollama)** and an analysis model. Cloud services reuse keys from **Connection Settings**. Ollama starts with the configured local URL/model and requires a vision-capable model, such as Qwen VL, Gemma 3 or LLaVA; a text-only Llama model cannot analyze a photo. **Load available models** retrieves OpenRouter vision models or installed Ollama models without running paid analysis.

**Generate Prompt** sends the image only to the selected analysis service. Cloud provider charges may apply. The result is an editable English positive prompt, not recovery of the exact original prompt. **Copy Prompt** copies it; **Use as Positive Prompt** replaces only MOSS's positive prompt, retaining the source, negative prompt, model, seed, LoRAs, sampler and denoise. Nothing is applied automatically. Closing cancels an active Ollama request; an already-started cloud request may continue at the provider, but its result is not applied.

The shared `ImagePromptButton` and `ImagePromptModal` accept a source `File`, a default format and an optional prompt callback, so other image surfaces can reuse the same dialog without importing MOSS settings.

Regression checks: `node --test services/imagePromptService.test.mjs services/openRouterService.test.mjs`. Provider calls are mocked; these tests do not establish live vision-model accuracy.

## Shared Character controls

**Character > Gemini**, **Character > Mammouth** and ComfyUI's multi-angle workflows share the same eight output slots. Gemini and Mammouth use the structured controls and identity/reference instructions from **Qwen 2.1 > Create Character**, not saved FLUX2 full-prompt overrides.

- Enable individual outputs, select/deselect all, randomize each output or the complete set, and expand/collapse the cards. The enabled slots determine the number of generated images, replacing the old cloud image-count/pose-list controls.
- Click the **Automatic Multi-Angle Set** accordion header (**Hide slots / Show slots**) to hide or reveal all eight cards without changing their values, enabled selections or individual expansion states. The toolbar remains accessible. **Expand all outputs** still expands the individual cards and also reopens the whole group when hidden.
- Each slot has **Camera Angle**, **Pose** and **Facial Expression**. Their dropdowns always expose every preset, even when a value is already selected; use **Custom...** to type arbitrary instructions without losing that ability. **Default (nothing)** and **None (same as photo)** remain available.
- The wide output column uses this order for all three providers: **Generate / Reset**, **Generated Content**, **Cancel Generation** (ComfyUI, while generating), then the **Automatic Multi-Angle Set** accordion and all eight slots at the bottom. Camera/pose/expression controls share a row on desktop and stack on mobile.
- Background and clothing controls support original content, prompts or reference images. Only active references are uploaded. **Green Screen** overrides stale background/preservation settings; **Preserve original background with new perspective** ignores a stored background reference.
- An optional pose reference can be uploaded or selected from the Library. An explicit per-slot pose takes priority; otherwise the reference supplies the pose. Identity, clothing, background and pose images are attached separately, in that order with absent roles omitted.
- Gemini and Mammouth submit one sequential request per enabled output, including all eight when selected. Results appear progressively. A failed request stops the remaining outputs and surfaces the error while retaining completed images.
- Cloud providers retain their own model/aspect-ratio controls and Gemini's supported image sizes/thinking settings. ComfyUI-only sampling, LoRA, Turbo and model-loader controls are not displayed as unsupported cloud features.

Regression checks: `node --test components/InputComponents.test.mjs services/cloudCharacterService.test.mjs services/characterAnglesWorkflow.test.mjs services/characterResults.test.mjs`. These checks use mocked providers and do not establish live model image quality or identity fidelity.

## Comparing Character results

Character keeps separate result sets for Gemini and Mammouth image models and for each ComfyUI multi-angle workflow/diffusion model. Qwen 2.1 Create Character's normal and Turbo modes have independent results.

- Switch providers, workflows or models with the existing selectors to compare their latest results. An unused selection starts empty; returning to a generated selection restores its images, output labels, final prompt, generation time and Library save indicators without generating again.
- A new generation replaces only the selected result set. Completed images remain available if later outputs fail or generation is cancelled.
- Library saves use the selected batch's original generation settings, identity reference and character name, even after the controls or source image have changed. ComfyUI images retain their individual seeds.
- Results stay available during the current app session. **Reset** clears generated results; save the versions you want to keep to the **Library** before resetting or closing the app.

## Qwen Image 2.1 T2I and Turbo

Image Generator has a separate **QWEN 2.1** family with **T2I** and **T2I (Turbo)** sub-tabs. Each mode retains its own prompt, models, sampling, size, orientation, and six LoRA slots in presets and Library generation options. Prompt Generator can send directly to either mode without resetting its existing settings.

- Both use `qwen_image_2.1_int8_convrot.safetensors`, `qwen3vl_8b_int8_convrot.safetensors`, and `qwen_image_2.1_vae_bf16.safetensors`, with native `TextEncodeQwenImage21` at resolution 1024 and `comfy kitchen attention`.
- T2I reproduces the supplied Low VRAM graph: KSampler, **25 steps, CFG 1, Euler, simple, denoise 1**. The reference `qwen21\p_qwen_image_2.1_8step_v0.1.safetensors` LoRA is present but disabled by default.
- Turbo uses its distinct `ModelSamplingFlux` -> `ModelAttentionBackend` -> `BasicGuider` / `SamplerCustomAdvanced` path. Flux shifts are **0.69 / 0.5**; BasicScheduler uses **6 steps**, Euler/simple/denoise 1, followed by `ExtendIntermediateSigmas` with **3 steps**, start -1, end 0.95, linear spacing. These are the exported graph values, not the conflicting four-step description in its notes.
- Turbo initially enables `QWEN\Qwen-Image-2.1-viggle-turbo-v0.2.1-6step-lora-r128.safetensors` at 1 and `qwen21\mvc5000_qwen21.safetensors` at 0.8, as in the supplied workflow. All six slots have independent enable switches, names, model strengths, and CLIP strengths serialized to `PixaromaLoraLoader`; the source graph connects only its model input.
- T2I base sizes: **1024x1024, 1152x864, 1248x832, 1376x768, 1536x1536**.
- Turbo base sizes: **1024x1024, 1152x864, 1248x832, 1376x768, 1920x1088, 1536x1536, 2560x1440, 2048x2048, 2400x1792, 2528x1696, 2752x1536**. Portrait reverses width/height; square sizes remain square. Both default to landscape **1152x864**.
- Pixaroma handles sizes, prompt, seed, LoRAs and PNG preview/save. Decorative notes, labels, and the run timer are omitted from the submitted graph. Returned PNGs are read directly without flattening transparency. Seeds support random, fixed, increment, and decrement across a batch.

Update ComfyUI and Pixaroma, install the selected weights/LoRAs, restart ComfyUI, then reconnect. Generation checks required nodes, model choices, sampling choices, attention and active LoRA availability before queueing. Nothing is downloaded or installed automatically. The supplied workflow notes identify research-license restrictions on Qwen 2.1 and Viggle Turbo; check the licenses of your exact weights before commercial use. Graph parity and simulated browser submission are tested; real GPU execution, VRAM usage, and image quality require validation on your ComfyUI installation.

## Qwen 2.1 multi-image edit

**Image Generation > ComfyUI > QWEN 2.1 > I2I Multi Images** supports one to four ordered references, with three slots initially matching the supplied workflow. Image 1 is always the main person; its role is locked. Other images can be another person, an object, background, clothing, pose, style or custom reference, each with an editable brief visual description and separate refinement instructions. Each image is analyzed only by clicking its **Analyze reference** button: importing images, changing roles/providers/reference counts and switching tabs never start analysis. Mammouth is the default for new/reset settings; Gemini 2.5 Flash and local Ollama vision models remain available, and saved provider choices are retained. Secondary-image analysis also receives the main person's image as context when available. API keys are configured in Connection Settings; Ollama needs an installed vision-capable model with multiple-image support. Failed analysis leaves the description manually editable. Library prompts and tags are never used as reference descriptions.

Each secondary reference has an **Interaction with main person** menu. Objects support holding in one/two hands, presentation and placement beside the person. Clothing is worn by the main person with natural, fitted or relaxed drape around their existing body shape, never by reshaping their body or copying the reference wearer. Additional people support left/right/behind placement, side-by-side positioning, facing each other, holding hands and a friendly side hug while keeping identities distinct. Analysis adds image-specific choices; for backgrounds it inspects visible usable seats and scene anchors to propose sitting on an actual chair/sofa or standing in an appropriate scene area, without requesting invented furniture. Selecting a choice immediately updates the automatic prompt. Changing a role/image clears incompatible descriptions and choices and cancels its pending analysis. Replacing the main person invalidates descriptions and analyzed interaction choices for every secondary reference, including hidden slots, without any automatic reanalysis; click **Analyze reference** to refresh each desired slot. Interaction choices and selections persist in Library snapshots, presets and workflow exports alongside refinements. With an active background reference, both automatic and manual final prompts include `Blend the person into the background image seamlessly.` once; inactive background slots do not trigger this addition.

The automatic prompt uses `<image1>` through `<image4>`, role-specific preservation instructions and scene composition; manual editing is optional. Native `TextEncodeQwenImage21` encodes that prompt and the images, with reference resolution 1024. The nine supplied canvas sizes and portrait/landscape orientation drive an independent `EmptyLatentImage`, not a reference-sized latent. Defaults retain 25-step Euler/simple, CFG 1 and denoise 1. The three-reference execution graph matches the attachment without decorative nodes; a fourth reference adds only its loader/encoder connection. Up to four optional LoRAs are available in the wide right column, before cache and attention. With empty slots the supplied graph stays unchanged.

Results display the generated image without reference comparison and support PNG download, LTX transfer and Library saving. No native Compare node is added. Library stores all references as separate assets with the submitted roles, descriptions, settings and actual seed; **Restore composition** restores them explicitly. The header and panel workflow exports use this panel's actual references. Required nodes, model choices and enabled LoRAs are checked before upload/queueing. No model is downloaded automatically. Simulated browser checks and live catalog compatibility do not certify real GPU output, image quality or VRAM usage.

Dependencies are checked before upload/queueing; no automatic downloads. Exact graph parity, simulated browser submission, native comparison, Library snapshots and desktop/mobile interaction are tested without GPU inference. ## Qwen 2.1 character sheet

In **Character > ComfyUI**, select **QWEN 2.1**, then **Character Sheet**. Existing QWEN Edit, FLUX2, Mammouth and Gemini character modes remain available. This first Qwen 2.1 sub-tab reproduces the supplied Character Sheet JSON without added LoRAs or generation/cropping nodes; only decorative labels and notes are omitted.

The four editable prompt blocks start with the reference examples: a full-body neutral-pose character sheet, three views in one row (front, right-facing side, back), matching identity/clothing/proportions/style, and a white background. Native text joining supports newline, comma, space, none or a custom separator, with optional empty-block skipping. Seven exact output sizes and landscape/portrait orientations are available, defaulting to **1920 x 1088**. Model, weight dtype, CLIP/device, VAE, attention, cache, reference resize method, resolution step, encoder resolution, negative prompt, sampler, scheduler, steps, CFG, denoise and seed are editable. Enter `-1` for a random seed; the actual submitted seed is saved.

The reference is loaded unmodified. `ComfyMathExpression` calculates the sheet's binary MP count; `ImageScaleToTotalPixels` determines the reference's aspect-preserving size; `GetImageSize` passes those dimensions to `PixaromaResizeCrop`, which reads the original. `TextEncodeQwenImage21` uses resolution 0 by default, while a separate `EmptyLatentImage` defines the sheet dimensions. Already saved images are skipped during bulk saving. View count (1-8) and vertical split positions are adjustable on the result. Crops retain every source pixel and PNG transparency. The sheet and each view have their own download/save actions. Library items preserve the original reference, actual submitted prompt/options/seed and crop coordinates; changes made after rendering do not alter that saved snapshot. Failed or cancelled runs retain the last successful sheet. Switching engines or main tabs preserves the session.

The default dependencies were checked against the local ComfyUI catalog; graph parity, transport, browser layout and PNG crop pixels are tested without GPU generation.
